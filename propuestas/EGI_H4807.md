# #EGI #H4807 Máquinas por tramos y causa en pausas

Los objetivos de este proyecto son:

+ Conocer la máquinas desde la que cada tramo de tarea se realiza
+ Conocer la causa de las pausas de producción

## Propuesta realizada a petición de:
Guillermo

## Estructura

### Máquinas
Crearemos un opción Máquinas en la que será posible crear máquinas y asociarles los tipos de tarea que realizan. Campos:

+ Id.
+ Descripción
+ Activa

Crearemos los casos de uso de *crear*, *modificar* y *borrar* máquina.
+ Condiciones:
    + Para Borrar
        + La máquina no debe tener tareas asociadas
        + La máquina no debe estar asociada a ningún tramo

Crearemos un caso de uso *asociar_tarea* en produccion/maquina
+ Entrada:
    + Id. Máquina
    + Id. Tipo Tarea

+ Condiciones
    + Máquina y tipo de tarea existen

+ Acción:
    + Asociar máquina a tarea

Crearemos un caso de uso *desasociar_tarea* en produccion/maquina
+ Entrada:
    + Id. Máquina
    + Id. Tipo Tarea

+ Condiciones
    + Máquina y tipo de tarea existen

+ Acción:
    + Desasociar máquina a tarea

El formulario o vista de máquinas permitirá activar los tipos de tarea desde una lista que mostrará todos los tipos y resaltará / filtrará los tipos ya asociados.

### Máquina en tramos
Cliente:

En la vista de inicio de tarea, si el tipo tiene una máquina o más asociadas, se pedirá al usuario indicar la máquina.

+ Si el tipo de tarea no tiene máquinas asociada, funciona como hasta ahora
+ Si el tipo de tarea tiene una máquina asociada, se autoselecciona la máquina
+ Si el tipo de tarea tiene más de una máquina asociada, se pide al usuario seleccionar una (radio button sin valor por defecto)

Servidor:
La acción de iniciar tramo admite un nuevo parámetro opcional *maquina_id* que se vuelca a un nuevo campo idmaquina en la tabla de tramos.

### Tipos de pausa
Crearemos una opción de tipos de causa. Campos:

* Id.
* Descripcion.

### Tipo de pausa en tramos

Cliente
+ En la vista de tramos, al pausar uno, se exigirá al usuario indicar una causa con los siguientes controles:
    + Tipo de causa (lista + opción _Otros_)
    + Descripción

La descripción será opcional salvo cuando se elija el tipo de causa _Otros_.

Servidor
Modificaremos el caso de uso de pausar tramo para recibir dos parámetros *causa_id* y *descripcion_causa* que se volcarán a dos nuevos campos idcausapausa, descripcionpausa, de la tabla de tramos.

### Desactivación de stocks
Modificaremos el comportamiento de Eneboo / Olula para que la funcionalidad de totalizar movimientos en stocks esté desactivada.

### Fecha de salida en pedidos
Empresa: Crearemos los siguientes campos

+ Un campo de texto largo _Festivos_ para indicar la lista de festivos con el siguiente formato:
    "2026-12-25;2026-12-26;2027-01-02;..."
+ Un campo días de servicio entero.

Crearemos una función sumarDiasLaborables que a una fecha sumará todos los días laborables saltando los sábados, domingos y días en la lista de festivos.

Calcularemos la fecha de salida del pedido como fecha pedido + días de servicio laborables en los siguientes casos:
+ Alta manual / modificación de la fecha del pedido
+ Alta de pedido desde presupuesto
+ Copia de pedido
